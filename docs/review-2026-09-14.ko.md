# 개선 제안 검토 — 2026-09-14

검토 대상은 사용자가 제공한 `kill game slop .txt`와 저장소의 기존 스킬입니다. Astra 단독으로 검토했으며 다른 모델이나 워커는 사용하지 않았습니다.

## 판단

보고서의 유효한 핵심은 **관찰 가능한 근거를 더 구체화하고, 편집을 실행하지 못하는 상황에서도 쓸 수 있는 명세를 제공하자**는 제안입니다. 기존 스킬에도 장르 보존, 접근성, 상태 정직성, 엔진별 확인 항목은 이미 있으므로 전면 재설계보다 실행 기준 보강이 적절합니다.

GI·MDA 등의 점수는 실험 데이터나 평가 척도의 검증 없이 부여되었습니다. 품질 측정값이나 개선 효과의 증거로 사용하지 않습니다. “업계 최고”, “필수 결함” 등의 표현 역시 제공된 자료만으로 입증되지 않습니다.

| 제안 | 판단 및 적용 |
| --- | --- |
| 구체적 슬롭 카탈로그 | 부분 채택. 빈번한 10개 후보에 증거·작은 수정·보존할 반례를 연결했습니다. 70개라는 수량 목표는 두지 않았습니다. |
| triggers·file_patterns·tools 추가 | 미채택. 표준 스킬 필드가 아니며 모든 호스트의 자동 인식을 보장하지 않습니다. 기존 유효한 frontmatter를 유지하고 description의 사용 조건을 명확히 했습니다. |
| 에디터 편집 명세 | 채택. 대상·근거·변경·범위·보존·검증·상태 템플릿과 엔진별 조건부 확인 항목을 추가했습니다. |
| 복사 즉시 실행하는 엔진 스크립트 | 보류. 구체적인 엔진 버전·프로젝트·자산 없이 범용 스니펫을 제공하면 검증되지 않은 API와 광범위 수정으로 이어질 수 있습니다. 필요할 때 실제 환경에서 생성·검증하도록 안내합니다. |
| 깊이·입자 수·키워드 기반 스캐너 | 보류. 깊이 10, 특정 폰트, “Tap to continue”만으로 결함을 판정할 수 없습니다. 반복된 실제 진단 과제와 정상/결함 예제가 확보될 때 검토합니다. |
| 멀티모달 검증 | 채택. 조건 기록 → 관찰과 추론 분리 → 동일 조건 비교 및 관련 스트레스 상황 확인으로 구체화했습니다. 정지 화면으로 동작·소리·성능을 검증했다고 말하지 않도록 했습니다. |
| 연출 예산 | 취지 채택. 반복되는 평시 신호와 의미 있는 절정 연출을 비교하되, 평시는 무조건 약하게 한다는 규칙은 두지 않았습니다. |
| 씬 텍스트 수정 전면 금지 | 미채택. 읽을 수 있는 원본의 작고 검증 가능한 수정까지 차단하지 않습니다. 바이너리·생성물·광범위 정규식 수정과 구분합니다. |
| 접근성 상위 원칙 | 기존 원칙 유지·보강. 이미 있는 다중 정보 채널과 모션 설정 보존을 구체적 반례에 연결했습니다. 단일 화면 확인을 접근성 규격 준수 증명으로 확대하지 않습니다. |

메타데이터 판단 기준: [Agent Skills specification](https://agentskills.io/specification). name과 description이 필수이며, scripts와 references는 선택 사항입니다. 실행 코드가 없다는 사실 자체는 스킬의 결함이 아닙니다.

## 적용 범위와 검증 한계

SKILL.md에는 핵심 판단 규칙과 참고 문서 연결만 추가하고, 상세 사례와 에디터 명세는 references로 분리했습니다. 한국어·영어 README에도 참고 문서의 역할을 안내합니다.

검증은 스킬 형식, 내부 문서 링크, 변경 내용과 기존 설치본의 일치 여부를 대상으로 합니다. 실제 게임 프로젝트나 엔진 런타임을 사용한 호환성·사용성 시험은 수행하지 않았으며, 새 사례도 측정 결과가 아닌 판단용 예제입니다.
