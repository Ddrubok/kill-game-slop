# Supplemental visual adjudication

During source review of repeats 1–2, before hidden scoring of worker outputs, the coordinator found a limitation in the frozen `visible pending cue` check. It compares selected-button background, border, shadow and outline, but not a newly rendered CSS `::before`/`::after` checkmark. A valid non-color cue could therefore be falsely rejected. The normal-mode check also samples the beginning of a CSS transition rather than its later frames.

Keep the original checker, its hashes and all machine scores unchanged. Run the same separate generated-content probe on all 12 outputs, preserving computed before/after pseudo-element properties and rendered captures for normal/system/local motion settings. If a machine failure concerns the visual cue, inspect that run's actual pending-state screenshot and source. Record any justified override separately by check name, evidence and reason. Do not override callback, timing, language, hit-target or motion-preference failures. The coordinating AI's visual adjudication is not blinded, independent or human scoring. Publish both machine-only and adjudicated outcomes, including the possibility that the limited task cannot establish a ranking.

The workspaces also inherit the parent repository for Git metadata. Some workers ran status/diff commands, exposing parent file names and producing ineffective diffs for ignored workspace files. Audit those commands and disclose this control limitation. Use direct original/final file hashes and independent runtime tests to judge edits; do not treat a worker's empty Git diff as proof of preservation. Do not exclude an otherwise unfavorable trial because of this shared setup limitation.
