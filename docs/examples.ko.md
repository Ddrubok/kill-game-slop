# 무엇을 바꾸고 무엇을 유지하나요?

[English](examples.md)

아래는 판단 방법을 설명하는 예시이며, 출시된 게임의 전후 측정 결과가 아닙니다.

| 게임 | 이전 | 이후 | 보존 |
| --- | --- | --- | --- |
| 아레나 슈터 | 모든 패널이 깜빡이고 체력 경고가 카메라를 흔듦 | 패널을 안정적으로 표시하고 체력 피드백이 모션 설정을 따르게 함 | 네온 팀 외곽선과 읽을 수 있는 위험 신호 |
| 아늑한 농장 | 당근을 수확할 때마다 축하 패널 세 개가 흐름을 끊음 | 실제 수확 결과를 한 번 표시 | 따뜻한 삽화와 중요한 목표 달성 연출 |
| 카드 대전 | 서버가 변경 가능한 선택을 받기 전에 “선택 확정!” 표시 | 대기 중 “선택 전송 중…”, 응답 확인 후 변경이 가능한 동안만 “선택 접수 완료 · 마감 전 변경 가능” | 서버 권한과 상대의 비공개 정보 |
| 픽셀 로그라이크 | 의도적으로 만든 화려한 테두리와 임시 설명 두 개 | 정확한 설명으로 수정 | 테두리, 픽셀 글꼴, 컨트롤러 포커스 |
| 이동 근접 공격 | 지면을 딛는 의도와 달리 공격 중 다리가 멈춘 채 미끄러짐 | 근거로 확인한 애니메이션·이동 불일치 수정 | 허용된 이동, 타격 구간, 고유 스타일 |
| 활주하는 캐릭터 | 고정된 다리 자세가 의도적으로 스케이팅을 표현 | 검토한 장면에서는 수정 불필요 | 의도된 추상 표현과 이동 공격 |

수리를 필수로 판단하려면 관찰된 기능·표현 불일치와 게임 의도에 따른 근거가 필요합니다. 눈에 보이는 불연속은 입력 실패를 측정하지 않아도 표현 결함일 수 있지만, 외형만으로 사람의 혼란이나 재미를 단정할 수는 없습니다. 두 문장을 고치는 것으로 충분할 수도 있고, 시각 변경이 정당화되지 않을 수도 있습니다.

판단은 확인된 결함, 가설, 선택적 개성 제안, 유지로 나눕니다. 소스 추적과 스크린샷은 서로 다른 주장을 뒷받침하며 어느 쪽도 플레이어 테스트로 제시하면 안 됩니다. 선택적 제안은 현재 버전과 작은 대안을 비교하고 이득·손실·성공 확인 방법을 설명합니다.

근거와 검증 방법은 공통 영문 지침인 [판단 예시](../skills/kill-game-slop/references/examples.md)를 참고하세요.
