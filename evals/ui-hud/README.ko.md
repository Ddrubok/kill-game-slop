# UI·HUD 회귀 평가

[English](README.md)

후속: [2026-11-06 일반·짧은·전체 비교](../runs/2026-11-06-comparison-utf8/report.ko.md)는 이 U·V 사례를 합성 기록 검토로 포함했고 모든 조건이 기준을 충족했습니다. 이는 같은 현재 버전에서 지시 조건을 비교한 것이며, 아래 과거 변경 전후·실행·사람 검사 열은 계속 NOT RUN입니다.

사용자의 UI·HUD 패치 안내 v1.0을 기준으로 2026-10-28에 준비했습니다. 일반 스킬 참조가 아닌 유지보수 자료입니다. 연계 bettermakegame 저장소에는 U01·U04·U05·U07이 있으며 어느 스킬도 다른 스킬을 필수로 요구하지 않습니다. 기존 평가 입력·결과는 보존합니다.

## 비교 절차

원문 [cases.md](cases.md)와 선택한 스킬 스냅샷만 사용합니다. 같은 모델·설정·입력·도구·범위로 변경 전후를 각각 새 대화에서 실행합니다. 이 절차, [judge-key.md](judge-key.md), 패치 설명과 이전 답변은 검토자에게 보내지 않습니다. 가능하면 무관한 스킬을 끄고 피할 수 없는 호스트 지침을 기록합니다. 전체 저장소 대신 `skills/kill-game-slop/`와 관련 참조만 제공합니다.

변경 전 버전은 `7baafa084f09686d02a01d2669f4557fee1db05d`입니다. 변경 후는 커밋 또는 정확한 스냅샷·파일 해시로 식별하며, 변하지 않은 기준 커밋을 수정 버전으로 표시하지 않습니다. 채점 전에 전달 프롬프트·원문 답변·도구 기록·자료를 저장합니다. 이 묶음은 합성 기록 해석을 시험하며 기록에 묘사된 캡처 자체를 제공하지 않습니다.

답변을 고정한 뒤 분리된 판정 기준을 사용합니다. 이 사례를 참고해 패치했으므로 미지의 시험으로 부르지 않습니다. U08 구현 평가에는 보고된 포커스 결함이 있는 실행 가능한 작은 프로젝트를 제공하고, 매번 시작 상태를 저장한 뒤 변경 내용과 키보드 행동을 확인합니다. 텍스트 답변은 제안 수정을 평가할 수 있지만 구현 성공을 입증하지 않습니다.

실제 상호작용·이해도 확인에는 작은 터치·키보드·컨트롤러 예제를 제공하고 처음 쓰는 사람에게 다음 행동 찾기, 상태 구분, 복귀를 요청합니다. 실제 관찰한 오류·도움·표본 한계·측정 시간만 기록하고 가능하면 비교 순서를 바꿉니다. 과거 합성 점수나 ChessAlkkkaegi 유지 사례를 이 패치·게임 전체의 근거로 재사용하지 않습니다.

## 보충 평가 v2

보충 안내 v2.0은 여기에 V05–V08을 추가하며 bettermakegame에는 V01–V04가 있습니다. 위 U 입력·판정 기준·상태는 첫 패치의 별도 기록으로 보존합니다. 안내 버전 2.0은 스킬 출시 버전이 아닙니다.

이 비교의 **변경 전** 커밋은 `7b79f19dfd103dff9d29b5bf601f9c159522e82b`입니다. 변경 후 커밋 또는 정확한 스냅샷 해시를 고정하세요. 같은 모델·설정·도구·입력으로 새 독립 대화를 열어 [supplemental-cases.md](supplemental-cases.md)와 해당 스킬 실행 지침만 제공합니다. 두 판정 기준, 이전 답변과 패치 설명은 제외합니다. [supplemental-judge-key.md](supplemental-judge-key.md)를 사용하기 전에 원문 프롬프트·답변·도구 기록·변경·캡처를 저장합니다. 위 실행 형식을 재사용하며 미실행과 시도했지만 기록된 제약으로 차단된 상태를 구분합니다.

합성 입력은 판단을 시험하며 묘사된 캡처나 실제 게임 동작을 시험하지 않습니다. V05–V07에는 정상·주입 조건을 포함한 작은 알림·수명주기 실행 예제가 필요합니다. 실행 사이에 시작 상태를 초기화하고, 실제로 도달할 수 있다고 가정하지 않은 채 지연 콜백과 재진입을 확인합니다. 기기·언어·설정·실제 관찰을 기록합니다. 사람 검사에는 구체적 과제를 사용하고 관찰한 도움·오류·시간만 기록하며 표본 한계를 공개합니다. 패치에 참고한 사례이므로 미지의 시험이 아닙니다.
