# kill-game-slop

[English](README.md)

**게임의 동작·규칙·표현이 함께 맞물리는지 검토합니다.**

어색한 행동 조합, 끊기는 상태 전환, 움직임·판정·피드백의 불일치, 복잡한 HUD와 잘못된 안내를 검토하고 다듬는 에이전트 스킬입니다. 게임의 의도를 기록하고, 확인된 결함·가설·선택적인 개성 제안·유지할 요소를 구분합니다. 수정 결과는 실제로 확인한 범위만 보고하며, **확인된 문제 없음**도 정상적인 결과입니다.

Unity·Unreal·Godot·Roblox·웹·자체 엔진에서 검토 기준으로 사용할 수 있습니다. 각 엔진과의 연동을 검증한 도구는 아니며, 스캐너나 AI 판별기를 설치하지 않습니다.

업데이트의 의미와 사용 예시는 [쉽게 읽는 업데이트 설명서](docs/update-guide-2026-10-14.ko.md)를 참고하세요.

| 이전 | 수정 |
| --- | --- |
| 서버가 받기도 전에 “선택 확정!” | 대기 중에는 “선택 전송 중…”, 응답 확인 후에만 “선택 접수 완료”, 실제 잠금 후에만 “선택 확정” |
| 적 표시만큼 밝게 빛나는 모든 패널 | 패널 강조를 줄이고 적 표시는 유지 |
| 게임에 잘 어울리고 읽기 쉬운 픽셀 장식 | 그대로 유지 |

설명을 위한 예제입니다. [판단 근거와 확인 항목](docs/examples.md)도 함께 제공합니다.

## 이 스킬에서 말하는 game slop

게임의 의도에 비춰 볼 때, 행동·규칙·움직임·피드백·콘텐츠의 연결이 덜 다듬어져 모순이나 어색함이 드러나는 완성도 문제를 뜻합니다. 이 스킬을 위한 작업 정의이며, AI가 만들었는지를 판별하는 기준은 아닙니다. 개별 기능이 작동해도 함께 실행하면 표현이나 동작이 어긋날 수 있습니다.

| 판단 기준 | 확인할 질문 |
| --- | --- |
| 행동 조합 | 이동하면서 공격하는 것처럼 허용된 행동들이 함께 성립하는가? |
| 전환과 복귀 | 시작·피격·취소·복귀 때 의도한 조작 권한과 상태가 유지되는가? |
| 공간적 일치 | 보이는 움직임·접촉과 실제 위치·충돌이 의도한 표현 방식에 맞는가? |
| 시간과 인과 | 입력·의미 있는 사건·소리·효과가 의도한 순서와 시간 기준을 따르는가? |
| 상태와 조작 | 화면이 알려주는 행동 가능 여부와 실제 입력 동작이 일치하는가? |
| 맥락과 개성 | 문구·아트·신호가 실제 사건을 게임 고유의 표현으로 전달하는가? |
| 반복과 마무리 | 반복해도 흐름·결과·강조가 유지되고 다음 행동으로 돌아갈 수 있는가? |

걷는 중 공격하는 것 자체는 결함이 아닙니다. 지면을 딛는 표현이 의도됐는데 지지하는 발이 미끄러지면 문제가 될 수 있지만, 의도된 스케이팅·부유는 정상입니다. 움직임 문제를 가리려고 허용된 이동을 막아서는 안 됩니다. 시전자가 중단됐다는 이유로 이미 발사된 투사체까지 지우지 말고 실제 수명 규칙을 확인합니다.

입력이 정상이어도 자세가 의도와 다르게 튀는 현상은 표현 결함이 될 수 있습니다. 관찰한 불일치와 기준이 된 규칙·시안을 기록하고, 원인이나 사람의 불쾌감을 확인한 것처럼 말하지 않습니다. 의도나 시간 흐름의 자료가 부족하면 가설로 남깁니다. 사실주의·고정 시간 오차·슬롭 점수를 보편 기준으로 강요하지 않습니다.

상세한 [게임 동작 정합성 안내](skills/kill-game-slop/references/gameplay-coherence.md)는 관련 행동·전환 작업에서만 읽습니다. 기존 UI·가독성 검사를 보완하며, 작은 문구 수정에 전투 전체 감사나 새 보고서 양식을 요구하지 않습니다.

```text
$kill-game-slop 이 캐릭터의 이동과 공격 조합을 검토해주세요.
진입·타격 피드백·중단·이동 복귀를 확인해주세요.
허용된 이동 공격, 타격 시점, 게임의 과장된 움직임은 보존해주세요.
관찰한 불일치와 의심 원인을 나누고, 수정 없이 보고해주세요.
```

## 판단과 근거

| 판단 | 처리 |
| --- | --- |
| 확인된 결함 | 요청받은 범위에서 수정하고 관찰 가능한 성공 조건을 확인 |
| 확인이 필요한 가설 | 부족한 근거와 원인을 구분할 확인 방법을 기록 |
| 선택적인 취향·개성 제안 | 기대 효과와 손실을 비교하고 현재 버전을 포함한 작은 실험 제안 |
| 유지할 요소 | 의도에 맞는 요소를 보존하고 검토한 조건을 명시 |

게임 의도 기록에는 플레이어의 행동, 전달할 감정, 보존할 시각·청각적 특징, 기기·입력 방식, 요청 범위를 남깁니다. 문서와 프로젝트에서 먼저 읽고 판단에 큰 영향을 주는 미확인 사항만 질문합니다. 스크린샷·영상·실행·소스·사용자 보고를 구분하며, 적용 완료와 검증 완료를 별도로 기록합니다.

정상 작동하는 UI라도 필요한 정보를 찾기 어렵거나, 버튼과 장식이 혼동되거나, 실제 입력 영역과 안내가 어긋나면 검토 대상입니다. 관찰한 사실·사용자 보고·가설을 구분하며, 겉모습만으로 오류율이나 이해도를 단정하지 않습니다. 새 UI·HUD 설계나 넓은 배치·개성 대안은 [bettermakegame](https://github.com/Ddrubok/bettermakegame)의 범위입니다. 두 스킬은 순서 제한 없이 독립적으로 사용할 수 있습니다. 둘 다 요청 범위에서 요소를 추가·단순화·이동·삭제할 수 있으며, 국소적인 사용성 수리에 bettermakegame 설치가 필요하지 않습니다.

## 핵심 정돈 영역

- **행동의 정합성**: 이동·공격·상호작용·중단·복귀가 어떻게 함께 작동하는지 확인합니다. 보이는 움직임, 실제 위치·접촉, 의미 있는 사건이 의도한 규칙과 맞는지 검사하고 정상적인 이동 공격과 의도된 추상 표현은 보존합니다.

- **UI / HUD와 조작**: 정보 가림, 버튼 식별, 실제 입력 영역, 포커스·뒤로가기, 불필요한 탐색을 확인합니다. 문제가 입증되지 않은 독특한 형태와 목적에 맞는 정보 밀도는 보존합니다.
- **텍스트 및 내러티브**: 반복이나 모호한 문구가 행동·규칙·복구 방법을 가리는지 확인합니다. 유용한 반복 안내와 게임의 말투를 보존하고 허용된 범위에서만 수정합니다.
- **시각적 가독성**: 실제 교전·이동에서 표적과 위험 표시를 확인합니다. 필요한 정보를 유지하는 중첩과 장식은 정상적인 표현으로 인정합니다.
- **모션 및 오디오**: 실제 정보 가림이나 조작 방해가 있는지 확인하고, 중요한 타격감과 보상 연출을 보존합니다. 정지 화면으로 소리나 반복 모션 문제를 단정하지 않습니다.
- **원작성 및 무결성 보존**: 의도된 아트 스타일, 게임 밸런스, 접근성 지원, 서버 권한 기반 네트워크 규칙을 훼손하지 않습니다.

일시적이거나 동시에 나타나는 표시에서는 시작 상태·발생 조건·근거를 기록하고, 수정 후 같은 순간과 직접 영향을 받는 주변 요소를 다시 확인합니다. 정상 플레이에서 도달 가능한 상태와 자동 입력·주입 상태를 구분합니다. 사각형 겹침은 의도된 포함 관계일 수 있고, AI가 뜻을 설명하지 못했다고 실제 사람이 혼란스러워한다고 단정할 수는 없습니다. 기하학 경고는 후보를 찾는 데 쓰고 실제 표시와 조작을 확인하며, 새 검사기를 요구하지 않습니다.

## 설치 방법

`kill-game-slop`은 `skills/kill-game-slop/SKILL.md` 파일에 정의된 이식 가능한 마크다운 스킬 패키지입니다.

Codex 및 호환 에이전트 환경에서 다음과 같이 설치할 수 있습니다:

1. `skills/kill-game-slop` 디렉터리를 에이전트 스킬 경로로 복사합니다:
   ```bash
   mkdir -p ~/.codex/skills
   cp -r skills/kill-game-slop ~/.codex/skills/
   ```
2. 다른 에이전트에서는 폴더 전체를 보존하고 `SKILL.md`와 연결된 참고 파일을 읽도록 지정합니다. 자동 탐색과 호출 문법은 사용하는 도구에 따라 다릅니다.

저장소를 다운로드한 뒤 해당 폴더에서 복사 명령을 실행하세요. Windows PowerShell에서는:

```powershell
New-Item -ItemType Directory -Force "$HOME/.codex/skills" | Out-Null
Copy-Item -Recurse skills/kill-game-slop "$HOME/.codex/skills/"
```

기존 설치가 있다면 개인 수정 내용을 비교한 뒤 교체하세요. 이 스킬은 Roblox용으로 시작한 `game-ui-craft`의 후속 버전입니다.

## 사용법 및 호출 예시

`$kill-game-slop` 명령과 함께 게임 장르, 화면 상황, UI 구조 또는 기획 문서를 제공하여 호출합니다.

### 프롬프트 예시

- **HUD 사용성 검토**
  ```text
  $kill-game-slop 이 HUD에서 정보 가림, 버튼 식별과 입력 영역,
  불필요한 탐색 부담을 검토해주세요. 확인된 결함과 가설을 구분하고,
  독특하지만 목적에 맞는 표현은 유지해주세요.
  파일을 수정하거나 화면 전체를 재설계하지 말고 근거와 최소 수정안을 보고해주세요.
  ```

- **아레나 슈터 (Arena Shooter)**
  ```text
  $kill-game-slop SF 아레나 HUD의 교전 장면을 검토해주세요. 피격 마커나 흔들림이 표적을 가리는지 조건과 근거를 확인하고, 의도한 타격감과 무기 밸런스는 보존해주세요. 수정 없이 확인된 문제·가설·유지할 것을 보고해주세요.
  ```

- **힐링 모바일 농장 게임 (Cozy Mobile Farm)**
  ```text
  $kill-game-slop 농장 게임의 상점·튜토리얼·보상 피드백을 검토해주세요. 반복이 실제 플레이 과제를 방해하는지 확인하고 유용한 안내·중요 보상·파스텔 스타일은 보존해주세요. 소리를 듣지 않고 마스킹을 단정하지 말고 수정 없이 보고해주세요.
  ```

- **픽셀 아트 로그라이크 (Pixel-Art Roguelike)**
  ```text
  $kill-game-slop 픽셀 아트 로그라이크의 마법 효과와 적 식별을 검토해주세요. 의도한 중첩과 확인된 정보 가림을 구분하고 1비트 스타일은 유지해주세요. 수정 없이 근거를 보고하며, 확인된 문제가 없어도 괜찮습니다.
  ```

## 예시 문서

구체적인 디자인 전후 비교 분석 및 시나리오 예시는 [docs/examples.md](docs/examples.md)를 확인하세요.

[평가 절차](evals/README.md)에는 12개 입력 사례, 분리된 판정 기준, 세 조건의 비교 방법이 있습니다. [첫 비교 결과](evals/runs/2026-10-14/report.md)는 합성 텍스트 사례와 AI의 잠정 채점이며, 짧은 프롬프트보다 우수하다는 결론은 내리지 않습니다. [ChessAlkkkaegi 실제 적용 기록](evals/real/chess-selection-2026-10-14/report.md)에는 로컬 실행 증거와 확인하지 못한 조건을 남겼습니다. 자동화 결과로 사람의 이해도나 선호를 대신 판단하지 않습니다.

[UI·HUD 회귀 평가 사례](evals/ui-hud/README.md)는 검토자용 입력과 유지보수자용 판정 기준을 분리합니다. 기존 U 사례를 보존하고 새 확인 항목을 다루는 V 사례를 추가했습니다. 두 묶음의 변경 전후 행동 평가는 모두 **NOT RUN(미실행)**입니다. 기존 비교와 ChessAlkkkaegi 기록을 어느 패치나 게임 전체의 검증 결과로도 재사용하지 않습니다.

개성 실험은 다음처럼 요청할 수 있습니다: `$kill-game-slop 이 카드의 의도한 감정을 확인하고, 결함과 선택적인 개성 제안을 나눠주세요. 현재 버전과 소수의 작은 대안을 비교하고, 보존할 것과 성공 조건을 알려주세요.` 검토만 요청하면 파일을 수정하지 않으며, 선택적 제안을 필수 수정으로 취급하지 않습니다.

설치되는 스킬에는 필요한 상황에서만 읽는 참고 문서가 포함됩니다.

- [프레젠테이션 검증](skills/kill-game-slop/references/presentation-checks.md): 구체적인 증상, 정상적인 반례, 동일 조건의 전후 화면 확인 절차
- [에디터 편집 명세](skills/kill-game-slop/references/editor-specs.md): 정확한 대상 지정, 참조 보존, 제안·적용·검증 상태 구분

자동 탐색을 위한 사용 조건은 description에 작성하며, 실제 호출 지원은 에이전트 환경에 따라 다릅니다. 비표준 triggers·file_patterns 필드에 의존하지 않습니다. [Agent Skills 규격](https://agentskills.io/specification)을 참고하세요.
