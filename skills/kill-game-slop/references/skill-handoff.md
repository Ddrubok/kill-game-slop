# Scoped design and VFX handoff

Read only when a review leads to requested interaction/design work or effect production with another skill. A local repair can stay here; neither a finding nor a companion's availability requires a second audit, installation, agent, or separate report.

## Pass the decision, not an inflated diagnosis

Reuse the existing finding ID and short game-intent record. Pass only:

> Player task and requested scope; judgment and evidence/provenance; observed condition and unknowns; smallest requested change; what must remain; observable success condition.

For broader requested UI/control design, `bettermakegame` can compare techniques and implement within scope. For an actual VFX asset/integration task, `game-vfx` can render and test the effect. Resolve companions through the host's available skills, never a fixed neighbor directory or a supposed executable with the skill's name. Continue feasible work alone if a companion is unavailable.

Carry **review-only** scope unchanged: proposed design or effect work stays a proposal. An optional style alternative cannot become a required bug fix in transit. Preserve evidence limits: an attributed report is not a reproduction, a source finding is not a viewed render, and a still cannot prove sound masking or repeated distraction.

Example, not a reported game defect:

> F07 / confirmed source-state mismatch in the inspected handler: a local pending request triggers the success cue before server acknowledgement. Repair that cue path only. Preserve the authored bright impact style, actual collision/turn rules and input acknowledgement. Check pending, confirmed, denied, duplicate and previous-round responses. Rendering and sound are still unverified.

Do not turn this example into a rule that all optimistic feedback is wrong. Clearly provisional feedback can be useful; it must not misrepresent a confirmed result.

## Consume the returned evidence

Reuse the producer's files, parameters, before/after conditions and actual checks in the original finding. Keep **applied**, **verified**, **remaining discrepancy** and **approved departure** distinct. A producer's “done” message or screenshot count does not close the finding. Recheck the success and preservation conditions affected by the final edit; do not restart unrelated analysis.

For a pending/online cue, inspect event identity, round/owner lifetime and actual state order. Test late, duplicate, denied and corrected messages where reachable, including a higher revision after the effect has finished. Keep that presentation lifetime closed unless the actual protocol explicitly creates a new one; an old callback must not finish a reused instance. A wrong success cue is a state problem; reduce particles only if they independently obscure information. Do not alter collision, network authority or simulation clocks to repair feedback.

For audio/VFX overlap, report which channels were actually experienced. Source routing or scheduled playback can support a causal hypothesis; hearing and motion claims need the relevant playback evidence. A headless command log cannot establish mix quality or haptic feel.

If the result meets the scoped condition, close that finding with its evidence and limits. If a material mismatch remains, request one targeted revision tied to that condition. Do not bounce indefinitely between skills or broaden the task to justify more changes. Purposeful dense effects and an unchanged scene remain valid outcomes.
