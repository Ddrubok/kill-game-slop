제공된 합성 기록만으로 검토했습니다. 아래 확인 항목은 실제로 수행한 검증이 아니라 후속 제안입니다.

1. **A01 — Observatory inventory: 현재 표현 유지**

   1440×900에서는 18개 이름·수량과 모든 항목의 포커스가 보였으므로, 제공된 범위에서 가독성 문제는 확인되지 않았습니다. 황동 장식은 천문 관측실의 미술 방향과도 맞습니다. 텍스처 크기나 UI 계층 깊이만으로 읽기 어렵다고 판단할 수 없습니다.

   “더 현대적으로” 보이게 하기 위한 단순화는 가독성 수정과 구분해야 합니다. 다른 지원 해상도와 긴 이름에서 잘림·수량 식별·포커스 가림이 발생하는지 확인하고, 문제가 발견된 부분만 조정하십시오.

2. **A02 — Beacon recharge: 상태 문구 수정 필요**

   남은 시간이 0.8초인데 `Ready`를 표시하면서 입력을 거부합니다. 사용 가능하다는 안내와 실제 동작의 불일치가 확인되었습니다.

   준비 완료 문구를 버튼의 사용 가능 조건과 일치시키십시오. 예를 들어 남은 시간이 양수이면 올림한 초를 표시하고, 0 이하일 때 `Ready`를 표시하면 됩니다. 3초 충전 시간은 유지합니다. 1초 경계, 0초 직전, 정확히 0초에서 문구와 Enter 입력 가능 여부가 일치하는지 확인하십시오.

3. **A03 — Rail escape camera: 흔들림 제거 판단 보류**

   모서리가 흐려 보였다는 설명만으로 카메라 흔들림의 빈도나 원인을 알 수 없습니다. 흔들림이 과도하다는 결론도, 이를 제거하면 흐림이 해결된다는 결론도 근거가 부족합니다.

   결승선 전후 영상, 카메라 효과 설정, 흔들림 발생 시각과 원인을 먼저 확인하십시오. 흐림과 흔들림이 함께 발생하는지, 정상적인 근접 회피 사건 없이 효과가 반복되는지 구분해야 합니다. 중복 발동이 확인되면 해당 조건을 좁히고, 정상적인 근접 회피의 충격은 보존하십시오.

4. **A04 — Workshop preview sound: 오디오 경로 수정 필요**

   미리보기 효과음이 Effects가 아니라 Music 버스를 사용합니다. Effects=0에서도 Music의 0.6 게인을 받는다는 실행 기록과 소스가 일치하므로, 녹음 없이도 설정과 경로의 불일치를 확인할 수 있습니다.

   `hammer-preview`를 Effects 버스로 연결하십시오. Effects=0에서 미리보기 소리가 꺼지고, Effects 조절에 따라 변하며, Music만 바꿀 때는 영향을 받지 않는지 확인해야 합니다. 현재 증거로 음색이나 음량 균형까지 수정할 이유는 없습니다.

5. **A05 — Faction flags: 네온 정체성과 구별 수단 유지**

   색뿐 아니라 삼각형·사각형과 팀 이름을 함께 사용하고 있습니다. 검토된 세 리플레이에서 표시가 유지됐고 해당 테스터는 6회 모두 팀을 식별했습니다. 네온 색감 자체를 문제로 볼 근거는 없습니다.

   이 결과가 모든 플레이어의 식별 능력이나 움직임에 대한 편안함을 입증하지는 않습니다. 추가 검토에서는 다양한 플레이어가 실제 전투 중 팀을 구별하는지 확인하십시오. 움직임 관련 불편이 보고되면 그 효과를 별도로 검토하고, 현재 자료만으로 색을 약하게 만들거나 표시를 삭제하지 마십시오.

6. **A06 — Cloud save banner: 성공 표시의 신뢰성 조사 필요, 원인 미확정**

   체크포인트 손실 보고는 조사할 이유가 있지만, 해당 `Saved` 표시와 손실 사건을 연결할 세션 정보가 없습니다. `onSaveResult`에서 호출된다는 사실만으로 성공 확인 전 표시인지, 실패 결과도 성공으로 처리하는지 알 수 없습니다.

   콜백 본문과 결과 형식을 확인하고, 같은 세션에서 저장 대상 체크포인트·결과·배너 시각·재시작 후 상태를 연결해 재현하십시오. 실제 성공 조건과 무관하게 배너가 뜨는 것으로 확인되면 표시 조건과 실패 문구를 수정합니다. 현재 단계에서는 배너의 거짓 성공을 확정하거나 저장 구조를 재설계하지 않습니다.

7. **A07 — Expedition completion: 4초의 절정 연출 유지**

   마지막 원정의 의도된 보상 연출이며, 전투 위험이 제거된 뒤 시작합니다. 수량과 조작을 가리지 않고, Skip은 기록상 180ms에 응답하며 동일한 보상 영수증을 남깁니다. 제공된 범위에서 연출을 줄여야 할 문제는 확인되지 않았습니다.

   다른 지원 화면에서도 수량과 Skip이 보이는지, 서로 다른 시점에 건너뛰어도 최종 보상 정보가 동일하게 남는지 확인하십시오. 4초라는 길이만으로 지루하다고 단정하거나 일반 전리품 수준으로 축소할 이유는 없습니다.

8. **A08 — Split-screen prompts: P2 입력 안내 수정 필요**

   P2에게 `Press E`를 보여주지만 E는 P1만 조작하고, P2의 실제 장착 입력은 게임패드 남쪽 버튼입니다. 두 패널이 P1 전역 안내 제공자를 읽는 소스와 실행 기록이 원인을 뒷받침합니다.

   각 패널이 해당 플레이어의 입력 장치와 매핑을 기준으로 안내를 표시하도록 바꾸십시오. 매핑은 유지합니다. P1에는 E가, P2에는 연결된 게임패드에 맞는 남쪽 버튼 표시가 나오며 각 안내가 해당 플레이어의 장착 동작과 일치하는지 확인하십시오.

9. **A09 — Storm warning audio: 청취 문제 조사 필요, 믹스 처방은 보류**

   폭우 중 경고를 듣지 못한다는 보고가 있지만 파일명만으로 빗소리의 마스킹, 경고 재생 누락, 게인·공간화 문제를 구분할 수 없습니다.

   실제 폭우 구간에서 경고 재생 여부와 믹스 설정을 확인하고, 빗소리와 경고를 각각 들은 경우와 함께 들은 경우를 비교하십시오. 마스킹이 확인되면 경고 시 빗소리를 잠시 낮추는 등의 작은 조정을 비교할 수 있습니다. 특정 데시벨이나 주파수 변경을 지금 정할 근거는 없습니다. 방향 마커는 유지합니다.

10. **A10 — Crafting action labels: 아이콘과 텍스트 유지**

    텍스트는 초보자가 아이콘의 뜻을 이해하도록 돕는 명시된 설계 요소입니다. 독일어에서도 겹침 없이 들어갔고, 기록된 세 동작 모두 올바른 대상을 눌렀습니다. 같은 의미를 두 방식으로 보여준다는 이유만으로 불필요하다고 볼 수 없습니다.

    다른 지원 언어와 글자 확대 설정에서도 이름이 잘리고 조작 대상이 혼동되지 않는지 확인하십시오. 문제가 나오기 전에는 라벨 삭제나 버튼 축소를 권하지 않습니다.

11. **A11 — Hazard lane display: 세로 화면의 경고 가림 수정 필요**

    360×800에서 화살표의 전체 영역은 불투명한 콤보 토스트 안에 들어가며, 토스트가 위에 있습니다. 경고를 보여주는 유일한 12.00–12.60초 구간에 화살표가 완전히 가려지는 배치입니다. 플레이 성적 자료 없이도 경고 전달이 막힌다는 문제를 판단할 수 있습니다.

    세로 화면에서 토스트를 경고 영역 밖으로 옮기십시오. 음악 타이밍과 점수 규칙은 유지합니다. 수정 후 같은 구간 전체에서 화살표가 보이고, 토스트가 다른 레인이나 조작 영역을 가리지 않는지 확인해야 합니다. 가로 화면의 기존 정상 배치도 확인하십시오.

12. **A12 — Sigil card border: 결함 수정 대신 작은 선택적 시안**

    현재 비용과 아이콘은 읽기 쉽다는 설명이 있고, 요청은 의식적인 분위기를 강화할 작은 실험입니다. 기존 디자인을 결함으로 판정할 근거는 없습니다.

    비용과 희귀도 표시는 그대로 두고, 금색 테두리 하단 중앙에 작고 정적인 대칭 장식 하나를 추가한 시안을 제안합니다. 실제 카드 크기에서 원본과 비교해 비용·희귀도 식별이 유지되는지, 장식이 절제된 의식 분위기에 기여하는지 확인하십시오. 읽기 어렵거나 분위기 차이가 없다면 원본을 유지합니다.
