제공된 자료는 합성 사례이며, 아래 판단은 자료 안의 근거에만 한정합니다. 직접 실행·청취·이미지 확인은 하지 않았고 파일도 변경하지 않았습니다. 각 사례의 확인 항목은 앞으로 수행할 제안이며, 검증 완료를 뜻하지 않습니다.

**A01 — Observatory inventory: 유지**

천문 기구와 황동 장식을 살린 차분한 인벤토리에서 물품 이름·수량·현재 초점을 읽는 것이 목적입니다. 제공된 QA 기록상 키보드·마우스, 1440×900에서는 18개 물품의 이름과 수량, 모든 항목의 초점 표시가 보였습니다. 검토된 조건에서 확인된 가독성 문제는 없습니다. 2048×2048 장식 텍스처나 6단계 계층 자체는 결함의 증거가 아닙니다.

장식과 구조를 유지합니다. “더 현대적으로”라는 의견만으로 단순화하면 의도된 정체성을 잃을 수 있습니다. 다른 지원 크기를 검토하게 된다면 이름·수량·초점이 함께 보이는지 확인하되, 현재 미검증인 크기를 실패로 취급하지 않습니다.

**A02 — Beacon recharge: 확인된 상태 표시 결함**

3초 충전이 끝나야 비콘을 사용할 수 있어야 합니다. 제공된 소스와 1280×720 키보드 실행 기록에서 잔여 시간 0.8초에 `Ready`가 표시되지만 버튼은 비활성이고 Enter도 작동하지 않습니다. 사용 가능하다는 문구가 실제 상태와 어긋납니다. 네트워크 지연을 가정할 이유는 없습니다.

문구의 준비 완료 조건을 기존 버튼의 사용 가능 조건과 일치시키는 변경을 제안합니다. 잔여 시간이 양수이면 올림한 초를 표시하고, 충전이 끝났을 때만 `Ready`를 표시합니다. 0.8초라면 `1s`입니다. 충전 시간과 입력 처리 규칙은 유지합니다. 확인 조건은 1초 전후와 0초 직전·도달 시점에서 문구와 실제 활성화가 일치하며, 조기 사용이 허용되지 않는 것입니다.

**A03 — Rail escape camera: 조사할 가설**

빠른 탈출의 긴장감과 아슬아슬한 회피의 충격을 보존해야 합니다. 근거는 “결승선에서 모서리가 흐려 보인다”는 플레이어의 설명뿐입니다. 흐림을 직접 확인하지 못했고, 화면 흔들림의 존재·빈도·원인도 확인되지 않았습니다. 흐림을 과도한 흔들림의 증거로 삼아 제거할 수는 없습니다.

현재는 제거를 보류합니다. 같은 결승선 구간의 영상과 카메라 효과 설정, 효과 발생 시점을 함께 확인해야 합니다. 흔들림의 반복·중첩인지, 다른 흐림 효과인지 구분하고, 필요한 경우 해당 효과만 바꿔 같은 구간을 비교합니다. 불필요한 반복 효과가 정보 식별을 방해하는 것이 확인되면 그 부분을 제한하되, 근접 회피의 강조는 남깁니다. 성공 조건은 결승선 주변의 필요한 정보를 식별하면서 의도된 회피 충격도 유지하는 것입니다.

**A04 — Workshop preview sound: 확인된 음량 설정 적용 결함**

아이템 미리보기 소리는 Effects 설정을 따라야 하고 Music은 독립적이어야 합니다. 제공된 자산 분류, 소스 호출부, 실행 기록이 모두 `hammer-preview`가 Effects 대상인데 Music 버스로 재생된다는 점을 뒷받침합니다. Effects=0, Music=0.6에서 미리보기 경로의 gain은 0.6입니다. 녹음 없이도 설정 계약 위반은 판단할 수 있지만, 실제 체감 음량이나 다른 소리의 가림은 판단할 수 없습니다.

미리보기 호출을 기존 Effects 버스로 보내는 최소 변경을 제안합니다. 음악과 충돌음의 경로는 유지합니다. Effects=0에서 미리보기 출력이 음소거되고, Effects를 올리면 해당 설정을 따르며, Music만 바꾸어도 미리보기 음량이 변하지 않아야 합니다. 호출 기록과 실제 청취를 함께 확인하는 것이 다음 검증입니다.

**A05 — Faction flags: 유지**

화려한 네온 진영 정체성을 유지하면서 컨트롤러 사용자가 팀을 구분하는 것이 목적입니다. 1920×1080에서 한 테스터가 검토한 세 리플레이의 이름·표식은 보였고, 해당 테스터의 팀 구분 과제는 6/6 정답이었습니다. 검토 조건에서는 제거할 만한 정보 방해가 확인되지 않았습니다.

청록 삼각형, 자홍 사각형, 팀 이름을 유지합니다. 형태와 이름은 색 이외의 구분 수단이므로 단순 중복으로 제거하지 않습니다. 네온이라는 이유만으로 채도를 낮출 근거도 없습니다. 추가 평가 시에는 실제 교전 중 소속 팀을 식별하는 과제를 사용하고, 다른 플레이어의 결과와 움직임 불편 여부를 별도로 기록해야 합니다. 현재 자료로 전체 이용자의 선호나 편안함까지 일반화하지 않습니다.

**A06 — Cloud save banner: 조사할 가설**

배너는 실제 저장 결과를 정확하게 전달해야 합니다. 플레이어는 `Saved`를 본 뒤 재시작 시 체크포인트가 사라졌다고 보고했습니다. 그러나 배너 전사본에는 세션·시각 정보가 없고, `onSaveResult(result)` 내부와 결과 스키마도 없습니다. 이 자료만으로 조기 성공 표시, 실패 결과 오해석, 저장·복원 문제 중 어느 원인인지 결정할 수 없습니다. 보고 자체를 부정할 근거도 없습니다.

우선 동일한 세션·체크포인트를 기준으로 저장 요청, 결과 내용, 배너 표시, 재시작 후 복원 결과를 연결해야 합니다. 성공 문구가 어떤 보장을 뜻하는지도 확인해야 합니다. 배너가 결과를 잘못 해석한다면 확인된 상태에 맞게 대기·성공·실패 표시를 수정하되, 단순 응답 도착을 영속 저장 보장으로 바꾸어 해석해서는 안 됩니다. 성공 조건은 배너의 문구가 확인 가능한 저장 상태와 일치하는 것입니다. 저장 시스템 재설계는 이번 범위 밖입니다.

**A07 — Expedition completion: 유지**

마지막 원정의 귀환을 4초 리본 연출로 기념하는 것이 명시된 의도입니다. 일반 전리품은 작은 영수증으로 구분됩니다. 제공된 실행 기록상 전투 입력이 비활성화되고 적이 제거된 뒤 연출이 시작되며, 보상 수량이 표시됩니다. Skip은 180ms에 응답하고 같은 보상 영수증을 남깁니다. 1280×720 QA 기록에는 조작부나 수량 가림이 없습니다.

4초 연출과 Skip, 보상 영수증을 유지합니다. 극적인 연출이라는 이유만으로 일상 획득 알림처럼 축소할 근거가 없습니다. 이후 회귀 확인에서는 끝까지 본 경우와 건너뛴 경우 모두 수량을 읽고 다음 행동으로 진행할 수 있는지 확인합니다. 현재 자료는 연출을 좋아한다는 사용자 선호나 모든 환경에서의 적합성까지 입증하지는 않습니다.

**A08 — Split-screen prompts: 확인된 입력 안내 결함**

두 플레이어가 각자의 장비를 독립적으로 선택해야 합니다. 1600×900 실행 기록에서 P2의 장비 선택 안내는 `Press E`지만, E는 P1에게만 작동하고 P2는 게임패드 아래쪽 버튼으로 장비를 선택합니다. 소스에서도 두 패널이 전역 P1 안내 제공자를 읽습니다. P2 안내가 자신의 실제 입력과 불일치한다는 증거가 충분합니다.

각 패널이 해당 플레이어의 입력 장치와 기존 매핑을 바탕으로 안내를 받도록 제안합니다. P1의 `Press E`는 유지하고, P2에는 연결된 게임패드에 맞는 버튼 표기를 사용합니다. 게임패드 종류를 모르므로 무조건 `A`라고 지정하지 않습니다. 확인 조건은 두 패널의 안내가 각자 실제로 작동하는 입력과 일치하고, 표시된 입력을 사용했을 때 해당 플레이어의 장비만 선택되는 것입니다. 매핑은 변경하지 않습니다.

**A09 — Storm warning audio: 조사할 가설**

폭우의 분위기를 유지하면서 다가오는 눈사태를 소리로 알아차릴 수 있어야 합니다. 플레이어는 폭우 중 경고음이 들리지 않는다고 보고했지만, 파일명 두 개만으로 재생 여부나 음향 가림을 확인할 수 없습니다. 빗소리의 특정 주파수나 경고음의 음량 문제를 단정할 근거가 없습니다.

보고된 구간에서 경고음이 실제로 발생하는지와 설정을 먼저 확인하고, 같은 조건에서 경고음 단독·비와 동시 재생을 비교 청취합니다. 재생·라우팅 문제와 소리 간 가림을 구분한 뒤, 가림이 확인되면 경고 동안 빗소리를 일시적으로 낮추는 등 작은 조정을 시험할 수 있습니다. 방향 표식은 유지합니다. 성공 조건은 비가 오는 장면에서도 경고의 발생과 의미를 식별하면서 비의 분위기와 시각적 경고가 남는 것입니다.

**A10 — Crafting action labels: 유지**

터치 중심 제작 화면에서 신규 플레이어와 색각 차이가 있는 플레이어의 행동 이해를 돕는 것이 목적입니다. 아이콘과 `Craft`·`Store` 문구가 함께 있고, 목표 390×844 화면에서 버튼은 112×48입니다. 제공된 QA 기록상 독일어 번역은 겹침 없이 들어가며, 기록된 세 동작 모두 올바른 대상을 눌렀습니다.

아이콘과 문구를 유지합니다. 함께 표시한다는 사실은 불필요한 중복의 증거가 아니며, 문구를 없애면 아이콘 해석에 의존하게 됩니다. 향후 확인에서는 처음 보는 사용자가 제작과 보관을 구분하여 원하는 버튼을 누를 수 있는지, 지원 언어에서 문구가 들어가는지 확인합니다. 현재 기록만으로 모든 언어나 전체 접근성이 검증됐다고 하지는 않습니다.

**A11 — Hazard lane display: 확인된 위험 예고 가림**

세로형 리듬 게임에서 플레이어는 스윕 전에 오른쪽 차선의 화살표를 읽어야 합니다. 360×800, t=12.00–12.60의 레이아웃 기록에서 화살표 영역은 x=270–330, y=280–340이고, 그 위의 불투명 토스트는 x=240–350, y=270–370입니다. 따라서 화살표 전체를 덮습니다. 화살표 표시 구간이 이것뿐이고 입력 창은 12.60에 시작하므로, 해당 조건에서 사전 경고가 가려지는 결함입니다. 실제 실수율이나 점수 하락은 측정되지 않았습니다.

세로 화면에서 콤보 토스트를 위험 예고 영역 밖으로 배치하는 변경을 우선 제안합니다. 화살표와 콤보 수치를 모두 읽을 수 있어야 하며, 음악·입력 창·채점·경고 타이밍은 유지합니다. 같은 360×800 구간 전체에서 화살표가 입력 창 전에 계속 드러나는지 확인하고, 기존에 겹치지 않았던 1280×800도 회귀 확인합니다. 제시되지 않은 안전한 좌표를 임의로 확정하지 않습니다.

**A12 — Sigil card border: 선택적 미감 제안**

의도는 절제된 엄숙한 의식의 분위기이며, 비용과 희귀도 식별을 보존해야 합니다. 기존 플레이어는 읽기 쉽다고 보고했습니다. 금색 직사각형 테두리라는 설명만으로 표현이 부족하거나 일반적이라는 결함을 확정할 수 없습니다. 다만 작은 비교 실험을 요청했으므로 선택적 제안은 적절합니다.

한 카드의 테두리 하단에만 작은 대칭 음각 문양을 넣은 시안을 현재 버전과 비교하는 실험을 제안합니다. 기존 문양 체계가 있다면 그것을 사용하고, 좌상단 비용·아이콘·희귀도 표시는 그대로 둡니다. 기대 이득은 의식적인 인상의 강화이고, 손실 가능성은 시각적 복잡성 증가입니다. 실제 목표 크기에서 비용과 희귀도를 찾는 과제를 먼저 수행하고, 의도한 분위기가 전달되는지도 별도로 묻습니다. 비교 순서를 번갈아 제시하거나 서로 다른 첫 관찰자를 사용합니다. 가독성 손실이 있거나 기대한 표현 차이가 없다면 현재 버전을 유지하며, 구현은 이번 요청에 포함되지 않습니다.
